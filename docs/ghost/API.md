# Ghost API Boundaries

Foundation draft, reviewed 2026-09-10. **CURRENT** describes this worktree;
**PROPOSED** is not executable. See [TERMINOLOGY.md](TERMINOLOGY.md) for names.
This is a concise boundary reference, not a duplicate tool manual.

## CURRENT: Agent Results

`agents.result(work_id=..., revision=...)` uses the normal native/Python tool
envelope; decode `content` JSON to read the nullable `snapshot`. Its optional
`research` contains stored outcome text, evidence resource refs, host candidate
IDs, optional unresolved questions, separate authoritative work/verification
usage, and accepted/applied/delivered instruction revisions. Summary text is
capped at 2 KiB UTF-8 and the broker result at 4 KiB, with at most eight refs per
list and explicit truncation. Missing answers and usage remain unknown, not
fabricated findings or zero bills. Usage totals are exact decimal strings
(including integer microUSD), with uncertainty for incomplete accounting.
No transcript or raw tool evidence is returned. See [AGENTS.md](AGENTS.md) for
availability, scope and revision-selection semantics. Python adds no policy.

## CURRENT: Research Metadata IPC

Tachyond accepts newline-delimited JSON over its Unix socket, not HTTP or a Ghost
tool. Source of truth: [ApiRequest/ApiResponse](../../crates/tachyon-api/src/types.rs)
and [research store](../../crates/tachyond/src/runtime_store/research.rs).
Each following JSON block is one request. Creation is inert: no worker, inference,
budget reservation, permission grant, scheduling, or launch occurs.

```json
{"cmd":"research_create","command_id":"docs-research-001","title":"Search correctness","objective":"Investigate workspace search behavior"}
```

Response shape (ID/time are illustrative server values):

```json
{"type":"research","research":{"id":"research-0123456789abcdef0123456789abcdef","title":"Search correctness","objective":"Investigate workspace search behavior","created_at_ms":1788998400000}}
```

Use the actual returned Research ID, not this illustrative ID, in these requests:

```json
{"cmd":"research_get","id":"research-0123456789abcdef0123456789abcdef"}
```

```json
{"cmd":"campaign_create","command_id":"docs-campaign-001","research_id":"research-0123456789abcdef0123456789abcdef","title":"Baseline audit","objective":"Describe a bounded search audit"}
```

Campaign create/get returns `{"type":"campaign","campaign":{...}}`. The record
contains `id`, `research_id`, `title`, `objective`, `created_at_ms`, and
`"status":"draft"`. Use its returned ID for get:

```json
{"cmd":"campaign_get","id":"campaign-0123456789abcdef0123456789abcdef"}
```

```json
{"cmd":"research_list","after":null,"limit":50}
```

```json
{"cmd":"campaign_list","research_id":"research-0123456789abcdef0123456789abcdef","after":null,"limit":50}
```

Research lists return `{"type":"research_list","records":[],"next_after":null}`;
campaign lists return `{"type":"campaign_list","campaigns":[],"next_after":null}`
for empty pages. Nonempty arrays contain the same records returned by get.

### Exact Creation Contract

- `command_id` is required for both creates, nonblank, at most 128 UTF-8 bytes.
  Both operations share one creation-receipt namespace in the runtime database.
- `title` and `objective` are required, nonblank, at most 256 and 16,384 UTF-8
  bytes respectively. Blank means `trim().is_empty()`; accepted text is preserved,
  not trimmed or normalized. These limits also apply to Campaign.
- An exact decoded request retry replays the original record, including ID and
  timestamp. Different fields or a different create operation with the same
  committed command ID conflict. JSON whitespace/key order are not payload changes.
- Record IDs are `research-` or `campaign-` plus exactly 32 lowercase hexadecimal
  digits, generated by the server. Campaign creation requires an existing Research.
- Receipt lookup, parent check, record/index insert, and receipt commit are one
  redb write transaction. Failed validation/parent checks leave no receipt; a
  successful commit remains replayable after reopening the database.
- Records are immutable; there is no update, delete, authorize, or launch variant.
  Errors use `ApiResponse::Error` (`type`, numeric `code`, `message`), not HTTP status.

### Exact Pagination Contract

- `limit` defaults to 50 when omitted and must be 1..100 inclusive.
- `after` is optional/null; otherwise it must be a syntactically valid ID of the
  listed record type. It need not identify an existing record.
- Results are ascending lexicographic ID order, strictly greater than `after`,
  not creation-time order. The campaign Research filter is applied before the
  page limit via the parent index; keep that filter unchanged between pages.
- Omitted/null `research_id` lists all campaigns. A well-formed nonexistent
  Research ID returns an empty page; a malformed filter is an error.
- `next_after` is the last returned ID only when another matching record exists;
  otherwise it is null. Pass it as the next `after` and stop at null. Each page
  has its own read transaction: pagination is not a multi-page snapshot, so new
  IDs inserted behind the cursor can be missed.

The store adds versioned Research/Campaign/receipt records and a parent index to
`runtime.redb`; it is not a campaign execution ledger. Dispatch clones the store
handle under the registry mutex, then releases that mutex before storage work.
redb serializes writers; a create may wait for that writer without holding the
registry. No model or external execution belongs inside that transaction.

## CURRENT: Ghost Tool Calls

These JSON objects are **function arguments**, not daemon requests. Policy and
installed packages determine availability; activation is not authorization.

| Function | Executable Arguments |
|---|---|
| `tools` | `{"action":"list"}` |
| `tools` | `{"action":"activate","package":"workspace"}` |
| `tools` | `{"action":"help","package":"exec"}` |
| `grep` | `{"pattern":"ResearchCreate","path":"crates","limit":20}` |
| `ipython` | `{"code":"workspace = require('workspace', asynchronous=True)\nresult = await workspace.grep(pattern='ResearchCreate', path='crates', limit=20)\nprint(result['content'])"}` |
| `exec` | `{"action":"start","argv":["/bin/printf","hello"],"timeout_ms":1000}` |
| `ctx` | `{"action":"list"}` |

Python `require` is synchronous metadata activation. Workspace methods are
awaitable with `asynchronous=True`; the default retains documented synchronous
compatibility. `workspace.search` remains a grep alias using `pattern`.
`proc = require("exec")` exposes awaitable `start/status/output/wait/cancel/run`;
`ctx = require("ctx")` exposes awaitable `read/list/search`. Each method sends the
native tool with `action` equal to its name and otherwise unchanged arguments,
returning a native envelope dictionary. No reference/timeout/size aliases exist.
Hostcalls execute on await with nonblocking I/O, but overlapping hostcalls are
rejected. One cell executes per kernel. Recursive IPython, browser, agents, and
history packages are not bridged. Direct tools are unchanged; see
[PYTHON.md](PYTHON.md) for copyable cells and cancellation limitations.

Native exec `start` acknowledges a pending supervisor before spawn/completion.
Use its exact returned `metadata.operation` in later **exec** calls (substitute
the returned string for `exec:<returned-uuid>`):

```json
{"action":"wait","operation":"exec:<returned-uuid>","wait_ms":1000}
```

Use its exact `metadata.stdout` reference object in **ctx**:

```json
{"action":"read","reference":{"id":"output:<returned-uuid>"},"cursor":0,"limit":8192}
```

```json
{"action":"search","reference":{"id":"output:<returned-uuid>"},"query":"hello","cursor":0,"limit":8192}
```

These reference-bearing examples are templates, not client-selected IDs. Wait
is bounded observation; inspect `done` and terminal result, and repeat observation
if pending. It does not extend execution time. `ctx` searches one bounded page,
not the workspace or all history. Output and execution handles expire at work
end and Ghost restart. Full limits/actions: [EXECUTION.md](EXECUTION.md).

## PROPOSED: Admission And Recovery

Future async delegation should return a durable Work handle at **admission**,
not imply worker/kernel allocation or return the child's answer. Results are
observed separately. A possible `handle = await agents.submit(...)` is design
pseudocode only: neither that package nor this signature is installed. The current
awaitable workspace/exec/ctx bridge does not provide delegation or durable admission.

Admission must atomically record identity, authorization, budget reservation,
and queued intent before execution. Execution later acquires independent
resource permits. Do not hold registry/resource-map locks or database
transactions across model calls, process completion, child-result waits, or
external side effects. See [RESEARCH.md](RESEARCH.md) for the root-ledger and
concurrency requirements; current metadata creation is not that admission API.

Recovery distinguishes an unstarted intent from an executed effect whose outcome
is unknown. Never blindly replay the latter: reconcile external state or require
an explicit retry decision with effect-specific idempotency. A timeout, kernel
loss, or disconnected waiter does not prove a write never occurred. Existing
Python/exec cleanup is local and does not provide durable exactly-once execution.
